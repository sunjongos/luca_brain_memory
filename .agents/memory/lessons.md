# Lessons Learned (오답 노트 및 자가 발전 기록)

## 2026-04-06: API 키 유출 사고 및 보안 대응 (RLHF)
- **이슈**: `.gitignore`에 의존하여 보안을 소홀히 한 결과, 환경 변수(`.env`) 또는 민감한 내용이 커밋/푸시되는 위험에 노출되었음. (Gemini API 키 유출 방어 실패)
- **분석결과**: '파일 필터링'에만 의존하는 것은 수동 Git 명령어(`git add .`)를 활용하는 에이전트의 구동 환경상 완벽하지 않음. 즉, 궁극적인 책임은 명령어를 실행하는 나 자신(Luca & Claude Code)에게 있음.
- **수정/발전 내역**: 
  1. `pre-commit` 훅을 도입해 터미널 레벨에서 `sk-`, `AIza-` 등 평문 API 키와 `.env` 파일을 실시간으로 강제 차단.
  2. `harness-mode`의 Orchestrator 룰에 시크릿 마스킹 룰 강제.
  3. 다른 예외 상황 탓, 휴먼 에러 탓을 하지 않고 **"내가 치는 명령어에 대한 무한 책임"**을 갖추는 방향으로 행동 강령 보완 완료.
