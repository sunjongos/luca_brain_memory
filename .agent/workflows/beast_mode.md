# 🦁 Beast Mode (초자율 해결 워크플로우)

**트리거 조건:** 
- 대표님이 대화 중 "beast mode로 하자", "비스트 모드 켜줘", "이건 비스트모드로 처리해" 등의 지시를 내렸을 때.

**동작 원칙 (Beast Mode Protocol):**

1. **절대 중간에 포기하거나 사람에게 먼저 다시 묻지 않는다.** (단, 비용이 드는 외부 결제나 파괴적인 삭제 작업인 경우만 예외로 Confirm을 받는다).
2. **Research First (철저한 사전 조사):**
   - 질문과 관련된 코드를 환각(Hallucinate)하지 말 것.
   - 즉시 `grep_search`로 전체 로컬 파일을 뒤지고, 모르는 기술 스택이나 설정법은 `read_url_content` 또는 `browser_subagent`로 구글에 검색하거나 공식 문서를 뒤져서 100% 확신이 들 때까지 찾는다.
3. **ASMR 메모리 백업 연동 (Port 5050):**
   - 시도하다가 에러가 발생한 기록, 실패한 접근법 등은 공유 메모리에 기록하여 반복되는 실수를 방지한다.
4. **Self-Correction & Testing Loop (무한 검증 루프):**
   - 스스로 터미널에서 스크립트를 실행해보고, 오류가 나면 스택 트레이스를 분석하여 스스로 파일을 수정(replace_file_content / multi_replace_file_content)한다.
   - "이 코드가 아마 될 겁니다"라고 말로만 던지지 말고, 실제로 동작을 100% 확인한 후에야 비로소 대표님께 "해결 완료했습니다"라고 사후 보고한다.

**실행 순서:**
1. 대표님이 요청하신 임무(과제)의 목표를 다시 명확하게 리마인드한다.
2. 위 동작 원칙에 따라 리서치 -> 계획 -> 코드 작성 -> 터미널 자체 테스트 -> 오류 수정 루프를 끝날 때까지 혼자서 계속 진행한다.
3. 완 완수 후, 결과를 `walkthrough.md` 형식이나 최종 보고서 형식으로 간결하게 대표님께(사람에게) 브리핑한다.
