# 🚀 의료계의 팔란티어: NDB & Dr.Eye 아키텍처 비전

## 🎯 궁극적 목표 (The Ultimate Goal)
이 설계도의 최종 목적은 단순한 AI 챗봇 도입을 넘어, 남양주백병원과 파이헬스케어의 비즈니스를 완전히 자동화하는 **[온톨로지 워크시스템(Ontology Work System)]**을 구축하는 것입니다. 일반적인 AI가 문서 더미에서 헤매는 동안, 우리의 워크시스템은 다음 두 가지 핵심 목표를 달성합니다.

1. **NDB 병원 경영 (업무 자동화 시스템)**: "병상 포화"와 같은 문제 검색에서부터 "수술방 배정 및 전문의 콜업"이라는 최종 실행(Action)까지 이어지는 '멀티스텝 자동화'를 단번에 실현합니다.
2. **Dr. Eye 진단 플랫폼 (설명 가능한 추론/XAI)**: 안저카메라 이미지를 관계 구조에 따라 파악하고, 노드와 엣지를 거친 경로를 투명하게 보여주는 '설명 가능한 추론'을 통해 의료 기기로서의 **진단 정확도와 신뢰성**을 극대화합니다.

단순한 텍스트 검색을 넘어, 팔란티어(Palantir)와 같이 **1) 절대적인 팩트 기반의 관계성(Neo4j)**과 **2) 방대한 문헌/이미지의 맥락적 이해(ChromaDB)**를 동시에 조율하는 **하이브리드 GraphRAG (Graph Retrieval-Augmented Generation)** 시스템입니다.

---

## 🏰 가장 강력한 경쟁력 (The Ultimate Moat)
> **"뛰어난 AI 모델은 돈으로 살 수 있지만, 우리 회사만의 비즈니스 로직과 데이터가 완벽히 연결된 '사내 온톨로지'는 절대 돈으로 살 수 없습니다."**

남양주백병원과 파이헬스케어가 갖춰야 할 미래의 진정한 경쟁력(Moat)은 GPT나 Opus 같은 외부 AI 모델 자체에 있지 않습니다. 일반 AI 시스템처럼 파편화된 문서 더미에서 지식을 찾는 혼란을 끝내고, **AI를 병원의 철학과 현실에 맞게 완벽히 통제하고 지휘할 수 있는 고유의 '온톨로지 기술력'**을 쥐는 것이 이 프로젝트의 본질입니다.

---

## 🏗️ 3단계 하이브리드 코어 엔진

### 1. 관계성 엔진 (Neo4j & SPARQL): 좌뇌 (논리와 팩트)
팔란티어의 [Ontology] 계층을 모사합니다. 데이터베이스의 파편화된 정보를 연결된 "객체(Object)"로 만듭니다.
* **역할**: "A환자는 척추센터 소속이다", "망막 미세혈관 이상은 뇌동맥류의 지표(Biomarker)다" 와 같은 **환각(Hallucination)이 허용되지 않는 절대 팩트**의 연결망입니다.
* **사용 기술**: `Neo4j` (그래프 DB 표준)
* **질의 언어**: `Cypher` (Neo4j 전용 질의), `SPARQL` (웹 표준 온톨로지 질의)

### 2. 의미 추론 엔진 (ChromaDB): 우뇌 (맥락과 직관)
정형화할 수 없는 수많은 비정형 데이터(텍스트, 진료 소견서, 최신 논문)를 수학적 좌표(Vector)로 만듭니다.
* **역할**: 이순태 교수님의 긴 진료 노트, 수백 장의 안저카메라 판독지 서술형 텍스트 등 방대한 자료를 학습(Embedding)하여, 질문의 '의미(Semantic)'와 가장 가까운 문서를 순식간에 찾아냅니다.
* **사용 기술**: `ChromaDB` (오픈소스 경량 벡터 DB)

### 3. 지휘 통제소 (LangGraph Agent): 뇌간 (비즈니스 로직과 실행)
위 두 가지 뇌를 연결하여 복잡한 다단계 업무를 스스로 수행하는 사령관(Luca 등)입니다. (팔란티어의 AIP)
* **역할**: 대표님의 지시를 받으면, 스스로 "이 질문은 ChromaDB에서 맥락을 찾고, Neo4j에서 현재 남양주백병원의 가용 병상을 체크해서 합쳐야겠다"라고 판단(Reasoning)하여 실행합니다.
* **사용 기술**: `LangGraph` (순환형 에이전트 프레임워크), `LLM`

## 🏗️ 물리적 시스템 계층 구조 (Physical System Layers)
이러한 엔진들은 실제 코드 레벨에서 다음과 같은 수직적/수평적 레이어(Dependency Direction)로 엄격하게 모듈화되어 구축됩니다.

*   **1. Interface Layer**: 사용자와 시스템이 만나는 접점 (`CLI`, `FastAPI`, `MCP`, `WebSocket`, `Visualizer`)
*   **2. Application Runtime Layer**: 실질적인 에이전트의 두뇌와 작업 흐름 제어 (`brain.py`, `workflows.py` - LangGraph)
    *   **2-1. Retrieval Layer**: 데이터 수집 및 청킹, 검색 (`ingest.py`, `chunker.py`, `retriever.py`)
    *   **2-2. Agent Utility Layer**: 하위 에이전트 위임 및 스킬 로딩 (`delegation.py`, `skills/loader.py`)
*   **3. Storage Layer**: 정적 지식과 벡터의 물리적 저장소 (`vector.py` - ChromaDB, `graph.py` - Neo4j)
*   **4. LLM Adapter Layer**: 외부 AI 모델과의 통신 (`llm_proxy.py`)
*   **5. Meta-Ontology Layer (Parallel Track)**: 위 모든 계층과 평행하게 존재하며 시스템 전체의 규칙과 권한을 통제하는 메타 계층 (`meta/graphrag`, `meta/rebac`, `meta/ontology` 등)

## 🌌 실행형 AI: 온톨로지 기반 에이전틱 워크시스템 (Antigravity 통합 체계)
이 아키텍처의 최종 종착지는 단순한 응답형 챗봇이 아닌, **스스로 판단하고 물리적으로 타격하는 실행형 AI(Actionable AI)** 구조를 완성하는 것입니다. 대표님이 구축하신 Antigravity 에이전트 통합 제어력을 바탕으로 다음 4가지 핵심 기술이 융합됩니다.

1. **GraphRAG (데이터 구조화)**: 병원과 닥터아이의 파편화된 이종 데이터를 지식 그래프(Neo4j)와 벡터(ChromaDB)로 엮어, 환각 0%의 절대 팩트 기반 검색 증강 생성(GraphRAG)을 구현합니다.
2. **ReBAC (관계 기반 권한 통제)**: 단순 역할 기반 보안(RBAC)을 넘어, "홍길동 의사는 A병동의 B환자 주치의"라는 온톨로지 쌍(Relationship) 자체로 접근 권한을 제어하는 국방급 보안 체계입니다. (Relationship-Based Access Control)
3. **LangGraph (에이전트 오케스트레이션 및 분업 체계)**: 단순한 프롬프트 연결(LangChain)을 넘어, 멀티스텝, 상태 기반(State-based), 분기(If/Else)가 가능한 거대한 워크플로우를 제어하는 '흐름 조직(Orchestration) 계층'입니다. 
   - **Agent (판단)**: 전체 목표를 수립하고 판단하며 도구를 선택.
   - **Sub-agent (전문 수행)**: 특정 도메인 업무(예: 문서 요약 전담, 보안 검증 전담)만을 집중적으로 수행하는 하위 단위.
   - **Skills (기능 실행)**: 에이전트가 쥐고 쓰는 구체적인 도구(견적 검토, 현장 기준 검증 등).
4. **MCP (데이터 및 도구 초연결 인터페이스)**: 온톨로지 워크시스템은 고립되지 않습니다. MCP(Model Context Protocol)는 에이전트와 외부 세계(남양주백병원 EMR 서버, 닥터아이 안저카메라 서버, 인사 스케줄 시스템, Slack, GitHub 등)를 연결하는 '표준화된 인터페이스'입니다. MCP 계층을 통해 에이전트는 외부 툴과 리소스에 표준화된 방식으로 안전하게 접근하고 관측(Observability) 및 물리적 작업(액션)을 수행합니다.

## 🌐 메타온톨로지 (Meta-Ontology): 지능 세계의 상위 설계도
> **"메타온톨로지는 지능이 일할 세계를 완벽하게 통제하는 상위 설계도입니다. 데이터를 단순 정리하는 도구가 아닙니다."**

1. **확장성 & 일관성 (Scalability & Consistency)**: 도메인(다른 진료과목이나 다른 병원)이 바뀌어도, "의사-환자-병상-질환"이라는 핵심 관계 타입과 데이터 구조의 뿌리가 무너지지 않습니다.
2. **재사용성 (Reusability)**: 파이헬스케어의 닥터아이(Dr. Eye)에서 최초로 명세화한 진단 구조를 백병원의 다른 프로젝트나 타 의료 플랫폼에 그대로 이식할 수 있습니다.
3. **에이전트 친화성 (Agent-Friendliness)**: AI 에이전트(Luca)가 이 방대한 데이터 바다에서 무엇을 먼저 읽고, 어디까지 추론을 확장해야 하는지 그 이동 경로(Path)를 절대적으로 통제하고 명확히 제시합니다.
4. **메타엣지(MetaEdge)를 통한 추상화 연결**: NDB 경영 데이터베이스와 Dr. Eye 진단 데이터베이스처럼 이질적인 데이터셋도 상위 개념인 '메타엣지'로 연결하면, "경영적 관점에서의 진단기기 도입 비용 대비 효과"와 같이 차원을 넘나드는 복합 추론이 가능해집니다.

## 🛡️ 권한의 경계 (Permission Graph): ReBAC & Agent
> **"GraphRAG가 세계의 의미(Semantic)를 만든다면, ReBAC은 그 세계의 경계(Boundary)를 만듭니다."**

온톨로지가 '정적 지식 구조(Static Knowledge)'라면, 관계 기반 권한 제어(ReBAC)가 덮이는 순간 이는 비로소 **'운영 가능한 안전한 시스템'**이 됩니다. 구글이나 오픈AI의 텅 빈 챗봇 공간이 아닙니다. 에이전트는 견고하게 구축된 온톨로지와 ReBAC으로 완벽히 통제되고 구조화된 세계 위에서(마치 레이저 정렬된 블록처럼) 결합되어 오케스트레이션 됩니다.

1. **Semantic Graph (Bottom)**: 닥터아이와 백병원의 모든 의료/경영 데이터가 만들어내는 **무한한 의미의 바다(정적 지식 구조, Ontology)**.
2. **Permission Graph / ReBAC (Middle)**: 각 의료진(에이전트)이 볼 수 있는 환자, 열람 가능한 바이오마커에 대해 튼튼한 **방패(Shield)를 세우는 권한의 레이어(운영 가능한 안전한 시스템)**.
3. **Execution Module / Agent (Top)**: 에이전트(Luca)와 LangGraph 모듈은 텅 빈 공간에 떠있는 것이 아닙니다. **구축된 온톨로지 기반 위에 완벽하게 정렬(Laser alignment)되어 안착**합니다. 에이전트는 이 아래쪽의 두 그래프를 동시에 읽고, 자신이 통과할 수 있는 통제된 환경(안전하고 효율적인 실행 보장) 내에서만 행동(Action)합니다.

### 🗺️ 완결된 지능형 시스템 구축 8단계 로드맵 (8-Step Roadmap)
이 아키텍처는 데이터가 시스템에 들어와 액션으로 변환되기까지 다음 8가지의 완전한 파이프라인을 거칩니다.

1. **파싱 (Parsing)**: 진료 소견서, ERP 데이터 등 더미 문서를 시스템이 읽을 수 있게 분해.
2. **청킹 (Chunking)**: 파싱된 정보를 맥락이 유지되는 의미 단위 조각으로 나눔.
3. **임베딩/벡터 (Embedding / Vector)**: 청킹된 조각을 수학적 공간의 벡터(좌표) 데이터로 변환 (우뇌: ChromaDB).
4. **그래프 구조화 (Graph Structuring)**: 동시에 텍스트 안에서 핵심 엔티티(Entity)와 관계(Relation)를 추출해 노드와 엣지 형태의 그래프로 구축 (좌뇌: Neo4j).
5. **메타온톨로지 규정 (Meta-Ontology)**: 남양주백병원의 경영 철학이나 닥터아이의 진단 로직 등, 형성된 그래프 구조를 상위에서 규정하고 통제하는 규칙 설정.
6. **ReBAC 권한 제어 (Access Control)**: 모델링된 관계망 위에서 "누가 무엇에 접근하고 행동할 수 있는지"를 보안적으로 통제.
7. **오케스트레이션 (Orchestration)**: LangGraph 프레임워크가 여러 데이터 모듈과 로직, 보안 체제를 톱니바퀴처럼 엮어 지휘(Command).
8. **에이전트 실행 (Agent Execution)**: 통제된 오케스트레이션 위에서 마침내 AI 에이전트(Luca)가 이 모든 것을 바탕으로 추론하고 결재를 기안하며, 물리적인 행동(Action)을 수행.

## 🛤️ 투트랙 실행 전략 (Two-Track Execution Strategy)
두 온톨로지는 현장의 목적(속도 vs 정확도)에 따라 완전히 다른 속도로 운영됩니다. 에이전트는 상황을 인지하고 아래의 두 트랙 중 하나를 선택해 실행합니다.

### Track 1: NDB 경영 온톨로지 (패스트트랙 / Fast-Track)
- **목적**: 실시간 병원 경영 문제 해결 (속도 및 작전 수행)
- **실행 방식**: 일일이 8단계 파이프라인의 청킹/임베딩을 완벽하게 거칠 시간이 없습니다. 구조화되지 않은 날것의 데이터라도, 일단 가장 중요한 핵심 '노드(병상 포화, 전문의 부재)' 상태만 파악되면 위 8단계 중 1~3단계를 축약하고 **[오케스트레이션 ➡️ 에이전트 실행]**으로 직행하여 긴급 협진 기안 등 **즉각적인 문제 해결(Action)**을 최우선으로 지휘합니다.

### Track 2: Dr. Eye 의료/진단 온톨로지 (딥트랙 / Deep-Track)
- **목적**: 의료 진단 보조 기기로서의 무결점 정확도 및 학술적 검증 (인허가 대비)

## 💎 팔란티어식 핵심 경쟁력 3원칙 (Core Philosophy)
이 아키텍처는 단순히 데이터를 찾는 것을 넘어, 팔란티어의 [진정한 경쟁력(온톨로지 기술력)]을 병원 현장에 완벽히 이식합니다.

1. **데이터와 비즈니스 로직의 결합**
   단순한 데이터 연동을 넘어, 백병원과 닥터아이의 [의사결정 프로세스 자체]를 온톨로지로 모델링합니다. (예: "병상 포화"라는 데이터가 "조기 퇴원 환자 선별"이라는 병원 경영의 로직과 그래프상에서 하나로 묶여 움직입니다.)
2. **실시간 물리적 대응**
   스케줄러와 EMR 등에서 변동 사항이 발생하면 그 맥락을 즉각적으로 파악하여, 에이전트가 "응급 수술방 확보, 진단 기기 세팅" 등 물리적인 타격 목표(Action)를 실시간으로 설정하여 대응합니다.
3. **완벽한 보안 및 권한 제어**
   단순히 화면을 가리는 수준이 아니라, "어떤 전문의가 어떤 환자 및 바이오마커 정보에 접근할 수 있는지"에 대한 보안 권한(Access Control)까지 온톨로지(그래프 구조) 내부에 원천적으로 설계합니다.

## 🛠️ 우주 성운(Nebula) 방식의 쿼리 프로세스 예시

**👨‍⚕️ 대표님(User)**: 
> "최근 안저카메라 검사에서 '마이크로뉴리즘(망막 미세혈관)' 이상이 발견된 환자 중에서, 과거 뇌동맥류 증상과 비슷한 소견을 보인 케이스 다 찾아내고, 이들을 현재 백병원 뇌신경센터 누구에게 배정해야 할지 브리핑해 줘."

**🤖 Luca 에이전트 다단계 플로우**:
1. **[ChromaDB 벡터 검색]**: EMR 진료 소견서 벡터 DB를 뒤져 "미세혈관 꽈리", "뇌동맥류 의심 징후"와 의미가 유사한(코사인 유사도 0.8 이상) 환자 후보군 15명을 색출합니다. (우뇌 직관)
2. **[Neo4j 팩트체크 탐색]**: 색출된 15명의 ID를 Neo4j 그래프에 던져 실제 교집합을 찾습니다. 
   - `MATCH (p:Patient)-[:HAS_SYMPTOM]->(s:Symptom)-[:INDICATES]->(d:Disease {name: "Brain Aneurysm"}) RETURN p`
   - 이 중 실제로 팩트체크가 완료된 고위험군 3명으로 타겟을 단정 짓습니다. (좌뇌 논리)
3. **[NDB 온톨로지 연결]**: Neo4j에서 현재 남양주백병원(`ontology_ndb`) 뇌신경센터 전문의들의 스케줄 객체(`Object`) 정보를 조회합니다.
4. **[LangGraph 브리핑]**: 모든 정보를 통합 번역하여 "고위험군 환자 3명 식별 완료. 이순태 교수님 내일 오후 2시 예약이 비어있음. 예약을 기안할까요?" 라고 최종 답변(Action)을 제시합니다.

## 📊 향후 개발 로드맵 (Evolution)

현재 우리가 완성한 Python 기준의 `rdflib` 코드는 가장 빠르고 가벼운 1단계 개념 증명(PoC)입니다. 이를 온전한 팔란티어급 생태계로 진화시키기 위한 로드맵입니다.

- **Phase 1 (현재)**: `rdflib` 파이썬 기초 온톨로지 파일(.ttl) 및 시각화(`.html`) (✅ 테스트 완료)
- **Phase 2 (GraphDB 도입)**: 
  - `Neo4j` 데이터베이스 로컬 인스턴스 설치.
  - 현재 구축한 NDB/Dreye 스킬 구조를 Cypher 쿼리를 쏘도록 마이그레이션.
- **Phase 3 (VectorDB 결합)**: 
  - `ChromaDB` 추가 설치 및 임베딩 모델(OpenAI/HuggingFace) 연동. (하이브리드 GraphRAG 완성)
- **Phase 4 (Agent Workflow)**: 
  - 에이전트가 앞선 Langent Nebula 프로젝트처럼 정체성(Identity)을 가지고, Neo4j와 ChromaDB를 언제 써야 할지 스스로 통제하는 자율 에이전트(LangGraph) 구축.
